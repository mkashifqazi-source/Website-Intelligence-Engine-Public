# Research failure model

| Failure | Acceptance consequence |
|---|---|
| Research output with no traversed evidence | Reject as research evidence; do not use its counts as targets |
| Schema-valid but unsupported assertion | Fails evidence/semantic review |
| Unresolved source reference | Cannot support an accepted signal |
| Stale or superseded source | Preserve history and assess current applicability |
| Contradictory platform documentation | Retain conflict/uncertainty until scoped reconciliation |
| Mathematical variants of one property | Deduplicate unless independent meaning is supported |
| Unobservable/private mechanism | Frontier record or explicit limitation |
| Unsupported ranking/AI-score claim | Anti-signal rather than authoritative dictionary |
| Incomplete coverage or saturation | Research gate remains open |

These are specified governance semantics rather than implemented MCP error codes. No public runtime retry/fallback protocol is selected.

Partial or sampled observations require explicit availability constraints. Missing evidence does not mean a feature is absent; an observed correlation does not establish causation. A later outcome cannot retroactively upgrade unsupported observations.

The long-term reconciliation problem is to compare claims that share compatible entity, platform, observation time and scope. The present project establishes the distinctions that such software would need; it does not claim an implemented reconciliation engine.
